# 按选定模型估算额度：可行性评估

日期：2026-10-13。基线：v1.3.4。本文保留评估依据；后续已完成公开参考、剩余额度换算与真实账户只读验证，实施范围与验证结果见[实施验证记录](model-quota-implementation-verification.md)。尚未正式发布。

## 结论

可以增加“选择模型 → 读取官方套餐规则、模型倍率与价格 → 展示模型对应额度和预估可用量”。但仅有每百万 tokens 单价，不能计算真实月度剩余额度；还需要账户所属套餐、计费类别、共享额度余额和适用折扣。

建议先实现“官方月度参考额度 + 实际窗口余量 + 按模型估算”，将估算与官网实测值分开展示。缺少真实月度余额时，明确显示“月度剩余暂不可得”，不能拿周窗口剩余比例乘以官网月额度。

上一份 [OpenDesign 订阅额度评估](opendesign-subscription-quota-assessment.md) 只分析了钱包中的订阅资金。它不能覆盖 Design Plan 的模型倍率等值额度，应以本评估补充后的双来源设计为准。

## 已验证的数据来源

### OpenDesign

- [官方模型额度规则](https://open-design.ai/model-credits/) 明确：Design Plan 模型共享额度；部分模型的额度倍数属于等值用量换算，不增加共享池余额。Design Plan 与套餐模型资金分开，适用窗口也不同。
- [官方价格页](https://open-design.ai/pricing/) 已提供“套餐 × 模型”的月度参考额度及每 7 天预估请求数。Go 当前示例：GPT-6 Luna 为 $15，Claude Haiku 5.5 为 $30，DeepSeek V4 Pro 为 $60，DeepSeek V4.1 Flash 为 $120。它们不能相加为四份独立额度。
- [官方前端数据](https://open-design.ai/cloud/assets/pricing-refund-policy-8aOZ9lOO.js) 的模型表包含 `multiplier`、`weeklyRequests`；展示公式为套餐基准除以模型倍率。该快照的套餐基准为 Go 60、Plus 80、Pro 180、Max 300。应动态读取并校验，不写成永久套餐常量。
- [公开模型价格接口](https://amr-api.open-design.ai/api/v1/public/model-prices) 本次无凭据 GET 返回 HTTP 200，包含 33 个模型，其中 8 个带长上下文分档。字段包括模型 ID、USD/百万 tokens、输入、输出、缓存读取、缓存写入及长上下文阈值。
- [官方控制台源码](https://open-design.ai/cloud/assets/cloud-root-X9i-hM9W.js) 还定义会话鉴权接口 `/api/v1/billing/model-discounts`，包含 `policyVersion` 和各模型 `discountPercent`。本次仅确认代码定义，未验证账户折扣响应。公开原价不一定等于账户实际扣费价。

因此，OpenDesign 的价格自动拉取可行性已由真实只读请求确认；模型倍率和套餐规则的自动同步仍需版本适配。现有 5 小时、7 天窗口可继续作为真实状态，不应把它们误作月度计数器。

### Command Code

- [官方 Max 规则](https://commandcode.ai/docs/plans/max) 列出标准与高级计费类别的不同额度，并指出类别取决于计费规则，不宜根据模型品牌推断。折扣、缓存和请求长度会改变实际可用量。
- [官方模型目录](https://commandcode.ai/models) 与 [定价规则](https://commandcode.ai/docs/resources/pricing-limits) 是套餐、模型价格和可用量参考来源。
- [Go 套餐说明](https://commandcode.ai/docs/plans/go) 将模型对应额度解释为共享池只用于该模型时的等值额度；混用模型按比例消耗。官方页面的 Next.js 数据中可提取模型 ID、计费类别、输入/输出/缓存价格、套餐预算、模型等值额度、预算分档及分时规则，但这属于页面数据格式，本次没有确认稳定的公开价格 JSON API。
- 官方请求数计算器采用固定的新输入、缓存读取和输出构成；不能将其结果直接视为用户剩余请求次数。个性化估算应使用明确假设或已有的实际用量统计，并补充适用的缓存写入计费。
- 公开模型目录 `GET https://api.commandcode.ai/provider/v1/models` 本次返回 HTTP 200 和 88 个模型，但没有价格或额度字段。因此现阶段不能仅依靠该模型目录接口完成价格同步。
- 当前本地 [CommandCodeUsageClient.cs](../Services/CommandCodeUsageClient.cs) 只读取通用 `monthlyCredits` 和窗口字段；[CommandCodeAllowanceWindowMethod.cs](../Services/QueryMethods/CommandCodeAllowanceWindowMethod.cs) 不接收模型选择，也未表达模型计费类别。因此不能直接认定当前返回的单一月度值对所有模型都适用。

Command Code 可先同步官方模型套餐表。将真实剩余额度换算到具体模型之前，仍须验证账户接口与该模型计费类别、共享池扣减口径的对应关系。

其 Go 文档还说明旧用户规则在续费时迁移，故当前官网套餐表不一定已经适用于所有存量账户。实际换算应识别规则生效版本；无法确认时只展示带日期的官网参考值。

## 估算规则

### 1. 模型对应的月度参考额度

优先读取官方“套餐 × 模型”的直接结果。若官方提供基准与倍率，则按同一口径计算：

`模型月度参考额度 = 套餐基准额度 ÷ 模型扣减倍率`

这一数值是完整周期的参考额度，不是当前剩余。上述公式已在 OpenDesign 当前官方展示代码中确认，不能未经核验套用到 Command Code。

### 2. 当前剩余额度

只有服务端返回归属明确的共享池余额，且模型倍率与该余额单位匹配，才可计算模型对应的等值剩余。若另有类别上限，须同时考虑该类别的实际已用或剩余。缺一项就保留真实窗口值，不伪造精确月余额。

共享池、独立类别上限、附加资金和充值资金应分别处理。切换模型只是更换换算视角，不创建新额度，不重置用量，不将多个模型的“可用额度”相加。

### 3. 预估可用 tokens 或请求数

在获得同一计费口径的可用金额后，可估算：

`单次成本 = (未缓存输入 × 输入单价 + 缓存读取 × 缓存读取单价 + 缓存写入 × 缓存写入单价 + 输出 × 输出单价) ÷ 1,000,000`

`预估请求数 = 可用金额 ÷ 单次成本`

各类 token 必须互斥，不能把已包含在输入总数中的缓存量重复计费。价格应根据总上下文长度选择档位，并按官方规则应用账户折扣或倍率，避免重复折扣。没有使用画像时，优先展示官网的请求数参考；自定义估算需说明输入、输出及缓存比例。免费模型显示“当前价格为零，仍受平台限制”，不能显示无限请求保证。

## 产品与代码建议

1. 加入独立“额度估算模型”选择。后续真实模型计费换算应使用精确 API 模型 ID 与显式别名映射，不使用模糊品牌匹配。第一阶段按照用户确认移除旧模型列表编辑框，以官网表格名称生成独立参考 ID；它不作为推理模型 ID。保留 Base URL、API Key、协议及配置中已有模型提示值。
2. 分别展示“官方月度参考额度”“当前窗口剩余”“预估可用量”。仅在接口提供可靠口径时增加“当前月度剩余”。订阅资金余额可另列，但不恢复钱包总余额作为 Design Plan 的替代值。
3. 增加价格/规则快照，记录来源 URL、抓取时间、套餐、模型、倍率、适用渠道及策略版本。建议每天刷新并提供手动更新；失效或解析失败时保留带日期的旧参考，不能显示为当前官方值。
4. 真实账户快照与估算结果采用独立数据结构或展示投影。现有模型含 `IsEstimated`，告警服务会排除估算值；新功能应维持这一边界，不覆盖实际窗口或官方余额。
5. 缓存键纳入模型 ID、套餐、账户/工作空间、价格及规则版本。模型切换不需要重新登录，也不影响其他页面数据。

## 验证范围与实施顺序

第一步实现模型选择与官方参考表同步，核对官网数值。第二步验证账户额度与模型扣减口径，再增加当前可用量换算。第三步在有可靠 token 构成数据时提供个性化请求数估算。

回归需要覆盖：模型切换与共享池不重复计入、类别限制、长上下文档位、缓存计费、折扣失效、免费模型、官网数据更新/缺失、未知套餐、API 与站内活动差异、账户/工作空间隔离，以及估算值不触发实际额度告警。

本次已完成公开价格接口与官方页面/源码核查。未执行付费模型调用，未验证新的账户级模型额度换算，未修改生产代码、配置或发布版本。
